# Аудиогид «Петергоф» · маршрут 343Э

Аудиогид для автобуса 343Э (Ломоносов → Петергоф → метро «Проспект Ветеранов»).
Следит за положением по GPS и сам включает рассказ, когда автобус подъезжает
к остановке. 29 точек, фото, карта маршрута, светлая и тёмная темы.

**Веб-версия:** https://s-smk17.github.io/peterhof-audioguide/

Один код на Expo (React Native) собирается в три варианта: Android, iOS и сайт.

**Как мы разрабатывали приложение с нейросетью** — пошаговый план со схемами
(для преподавателя и школьников): [docs/development-plan.md](docs/development-plan.md)

## Что внутри

| Часть | Технология |
| --- | --- |
| Приложение | Expo SDK 57, React Native 0.86, TypeScript |
| Карта (телефон) | `@maplibre/maplibre-react-native`, тайлы OpenFreeMap |
| Карта (сайт) | `maplibre-gl` v6 — тот же движок MapLibre, версия для браузера |
| GPS | `expo-location` + `expo-task-manager` (фон); в браузере — `navigator.geolocation` |
| Звук | `expo-audio`; в браузере — свой плеер на `<audio>` |
| Хранение настроек | `@react-native-async-storage/async-storage` (в браузере — localStorage) |
| Веб | `react-native-web`, `react-dom`, `@expo/metro-runtime` |

Структура:

```
App.tsx                  экраны, навигация, связка GPS ↔ плеер
src/screens/             Главная, Гид, Маршрут, Ещё (настройки)
src/components/          карта, мини-плеер, нижнее меню, UI
src/location/            GPS, геометрия маршрута, пешеходный путь до остановки
src/audio/               плеер рассказов
src/data/route.ts        29 остановок: названия, координаты, фото, аудио
assets/                  фото остановок и mp3
public/                  шаблон index.html, манифест и иконки для сайта
.github/workflows/       автопубликация сайта на GitHub Pages
```

```bash
npm install
npm start          # Metro: QR-код для телефона, клавиши a / i / w
npm run web        # сразу открыть в браузере
```

## Развёртывание на телефоне

> Команды — для Expo SDK 57. Перед работой сверяйтесь с документацией
> нужной версии: https://docs.expo.dev/versions/v57.0.0/ (в EAS иногда меняются
> флаги и профили).

Есть три способа, от самого быстрого к самому «настоящему».

### Способ 1. Expo Go — посмотреть за минуту

1. Установите **Expo Go** из Google Play / App Store.
2. Компьютер и телефон — в одной Wi‑Fi сети.
3. `npm start` → отсканируйте QR-код (Android — в Expo Go, iPhone — камерой).

Ограничения Expo Go для этого проекта:

- **нет нативной карты MapLibre** — приложение само это определяет и
  показывает упрощённую схему (`SchematicMap.tsx`, см. `MapView.tsx`);
- **нет фоновой геолокации** — гид работает, только пока приложение на экране.

Если телефон не видит компьютер (другая сеть, VPN): `npx expo start --tunnel`.

### Способ 2. Development build — всё работает, код обновляется на лету

Это «своё Expo Go» со всеми нативными модулями проекта.

**Локально, Android** (нужны Android Studio и SDK, телефон по USB с включённой
отладкой или эмулятор):

```bash
npx expo run:android
```

**В облаке через EAS** (Android Studio не нужна):

```bash
npm install -g eas-cli
eas login
eas build --platform android --profile development
```

По окончании EAS даёт ссылку и QR-код — установите приложение на телефон, затем
`npm start` и откройте проект в установленном приложении.

### Способ 3. Сборка для установки (APK) — показать преподавателю, раздать друзьям

```bash
eas build --platform android --profile preview
```

Профиль `preview` в `eas.json` — внутреннее распространение: EAS выдаёт ссылку,
по которой файл ставится на любой Android (разрешите «установку из неизвестных
источников»). Если вместо `.apk` пришёл `.aab`, добавьте в профиль:

```json
"preview": { "distribution": "internal", "android": { "buildType": "apk" } }
```

Для Google Play — профиль `production` и `eas submit`.

### iPhone

- Expo Go работает бесплатно (с ограничениями выше).
- Установить собственную сборку на iPhone можно только с аккаунтом
  **Apple Developer** (платный): `eas build --platform ios --profile development`
  или `--profile preview`, устройство регистрируется через `eas device:create`.
- Без аккаунта Apple на iPhone удобнее всего пользоваться **веб-версией**.

### Что проверить на телефоне после установки

- [ ] Разрешение геолокации: сначала «При использовании», затем «Всегда»
      (Ещё → GPS должен показать «В фоне»)
- [ ] Карта показывает маршрут, синюю точку «вы здесь» и ближайшую остановку
- [ ] Рассказ запускается у остановки, в том числе с выключенным экраном
- [ ] Вне маршрута — голосовая подсказка «вы не на маршруте»
- [ ] Прогресс и настройки сохраняются после перезапуска

## Веб-версия: как устроена и как публикуется

### Платформенные файлы `.web.ts(x)`

Сборщик Metro для сайта сначала ищет файл с суффиксом `.web`. Так мы заменили
только то, чего в браузере нет, а остальной код (экраны, данные, логика маршрута)
общий с телефоном:

| Файл для браузера | Чем отличается от версии для телефона |
| --- | --- |
| `src/components/MapView.web.tsx`, `RouteMap.web.tsx` | карта на `maplibre-gl` вместо нативного модуля; те же тайлы, слои и логика камеры |
| `src/location/locationService.web.ts` | `navigator.geolocation` вместо фоновой задачи; Wake Lock, чтобы экран не гас |
| `src/audio/useGuideAudio.web.ts` | два постоянных `<audio>`, которые «разблокируются» первым касанием (см. ниже) |
| `src/location/externalMaps.web.ts` | Яндекс Карты / 2ГИС — сайты в новой вкладке вместо приложений |

Плюс в `SettingsScreen.tsx` для браузера другие подсказки про геолокацию,
а в `ui.tsx` размытие фона на сайте только у плавающих панелей
(`Platform.OS === 'web'`).

Воркер карты (`maplibre-gl-worker.mjs`) — отдельный файл. После `npm install`
скрипт `scripts/copy-maplibre-worker.mjs` сам копирует его в `public/`.

### Локальная сборка

```bash
npm run build:web            # = expo export --platform web → папка dist/
npx serve dist               # открыть http://localhost:3000
```

### Публикация на GitHub Pages

Делается автоматически: каждый push в `main` запускает
`.github/workflows/deploy-web.yml` — `npm ci` → `expo export` → публикация.
Ход сборки — во вкладке **Actions** репозитория. Запустить вручную:
Actions → *Deploy web app* → *Run workflow*.

Однократная настройка (уже сделана):

1. Репозиторий публичный (для приватных Pages работают только на GitHub Pro).
2. Settings → Pages → Source: **GitHub Actions**.

Почему нужен `app.config.js`: сайт живёт не в корне домена, а в
`/peterhof-audioguide/`. Workflow передаёт этот путь через переменную
`EXPO_BASE_URL`, и Expo подставляет его во все ссылки на скрипты, фото и аудио.
Локально переменная не задана — сайт работает из корня.

Сайт можно установить как приложение (PWA): Safari → «Поделиться» →
«На экран Домой», Chrome → меню → «Добавить на главный экран».
За это отвечают `public/manifest.json` и иконки в `public/`.

## Как тестировать веб-версию

### 1. На компьютере (Chrome)

1. `npm run web`.
2. DevTools (F12) → значок телефона (**Device toolbar**) → выберите, например,
   iPhone 14.
3. DevTools → ⋮ → More tools → **Sensors** → Location → задайте координаты.
   Так можно «проехать» маршрут, не выходя из дома. Примеры:

| Где | Широта | Долгота | Что должно произойти |
| --- | --- | --- | --- |
| Остановка 1, Ломоносов — Вокзал | 59.9174888 | 29.7699554 | «На маршруте», рассказ точки 1 |
| Остановка 2, Еленинская улица | 59.9141728 | 29.768976 | рассказ точки 2 (или в очередь, если играет точка 1) |
| Центр Петергофа (на маршруте) | 59.8806 | 29.9087 | «На маршруте», следующая остановка |
| Фонтан «Самсон», 600 м от маршрута | 59.8857 | 29.9083 | «Вне маршрута», пеший путь до ближайшей остановки, голосовая подсказка |

Остальные координаты — в `src/data/route.ts`.

Важно про звук: браузеры не дают включать звук, пока человек не коснулся
страницы. Поэтому сначала кликните в любое место, потом меняйте координаты —
рассказы будут запускаться сами.

### 2. На телефоне

Геолокация в браузере работает **только по HTTPS** (исключение — `localhost`
на самом компьютере). Адрес вида `http://192.168.1.5:8081` с телефона GPS не
получит. Поэтому на телефоне тестируем опубликованный сайт на GitHub Pages
(или запускаем `npx expo start --tunnel` — туннель даёт HTTPS-адрес).

### 3. Чек-лист перед сдачей

- [ ] Все 4 вкладки открываются, нет пустого экрана
- [ ] Карта загрузилась: линия маршрута, остановки, точка «вы здесь»
- [ ] Кнопка ⤢ открывает карту на весь экран, ✕ закрывает
- [ ] ▶ играет рассказ, работают перемотка ±15 с и скорость 1×–2×
- [ ] После первого касания рассказ у остановки запускается сам
- [ ] Вне маршрута — подсказка и кнопки «Яндекс Карты» / «2ГИС»
- [ ] Тема: «Светлая» / «Тёмная» / «Как в системе» — карта тоже меняется
- [ ] После перезагрузки страницы прогресс и настройки на месте
- [ ] При запуске вдали от маршрута голос молчит; сошли с маршрута —
      «вы не на маршруте», вернулись — «вы снова на маршруте»
- [ ] Уже прозвучавшая остановка не повторяется в той же поездке, но звучит
      на обратном пути (и через час без остановок)
- [ ] Нижняя панель вкладок стоит на месте при прокрутке, в том числе у края
- [ ] Отказ в геолокации → «Нет доступа к GPS» и кнопка «Повторить»
- [ ] Сайт открывается по ссылке GitHub Pages, в консоли нет ошибок 404

### 4. Автотест в браузере (Playwright)

Так проверял ИИ: скрипт открывает сайт в Chromium с подставной геопозицией,
нажимает кнопки и делает скриншоты.

```js
// smoke.mjs — запуск: npm i -D playwright && npx playwright install chromium
//                     npm run build:web && npx serve dist   (в другом окне)
//                     node smoke.mjs
import { chromium } from 'playwright';

const browser = await chromium.launch();
const context = await browser.newContext({
  viewport: { width: 390, height: 844 },                  // размер iPhone
  geolocation: { latitude: 59.8806, longitude: 29.9087 }, // Петергоф, на маршруте
  permissions: ['geolocation'],
});
const page = await context.newPage();
page.on('pageerror', (e) => console.log('Ошибка на странице:', e.message));

await page.goto('http://localhost:3000');
await page.getByText('НА МАРШРУТЕ').waitFor();          // GPS сработал

// Касание страницы — после него браузер разрешает звук
await page.getByText('Добро пожаловать').click();

// «Подъезжаем» к остановке 2 — рассказ должен включиться сам
await context.setGeolocation({ latitude: 59.9141728, longitude: 29.768976 });
await page.waitForTimeout(3000);

await page.getByText('Гид', { exact: true }).click();
await page.screenshot({ path: 'guide.png' });

const text = await page.innerText('body');
const ok = text.includes('Еленинская улица') && text.includes('Ⅱ'); // Ⅱ — кнопка паузы
console.log(ok ? 'OK: рассказ о точке 2 играет' : 'ОШИБКА:\n' + text);

await browser.close();
process.exit(ok ? 0 : 1);
```

## Как мы собирали веб-версию с ИИ

Журнал работы с Claude Code — что делали и какие проблемы встретили.

1. **Анализ проекта.** ИИ прочитал код и решил не писать сайт с нуля, а
   собрать веб-версию из того же Expo-проекта: экраны и логика общие,
   заменяются только нативные части.
2. **Зависимости для веба.** `react-dom`, `react-native-web`,
   `@expo/metro-runtime` — версии взяты из списка, совместимого с SDK 57
   (`expo/bundledNativeModules.json`). Обычно это делает
   `npx expo install ...`, но в среде ИИ не было доступа к серверам Expo.
3. **Первый запуск — белый экран.** Ошибка `codegenNativeComponent is not a
   function`: нативная карта MapLibre не работает в браузере. Решение —
   `RouteMap.web.tsx` на `maplibre-gl`.
4. **maplibre-gl v6 не заработал.** Он подгружает свой веб-воркер через
   `import.meta.url`, а сборщик Metro так не умеет. Сначала перешли на v5, где
   воркер встроен в бандл. Потом `npm audit` нашёл в v5 уязвимость, и мы
   вернулись на v6: воркер копируется в `public/` скриптом, а адрес ему
   задаёт `setWorkerUrl`.
5. **Карта нулевой высоты.** CSS-класс карты (`position: relative`) перебил
   стили react-native-web. Нашли, измерив элементы в браузере через Playwright.
   Решение — отдельный DOM-элемент с инлайн-стилями.
6. **Звук.** Браузеры блокируют автозапуск без касания. Нашли баг: после
   заблокированного автозапуска первое нажатие ▶ ничего не делало. Плюс Safari
   разрешает звук конкретному `<audio>`, а `expo-audio` в браузере создаёт новый
   на каждый трек. Написали свой веб-плеер на двух постоянных элементах,
   которые «разблокируются» первым касанием.
7. **GPS в браузере.** Фоновой геолокации нет — добавили Wake Lock, чтобы экран
   не гас, и честные подсказки в настройках.
8. **Публикация.** PWA-манифест и иконки, `app.config.js` с базовым путём,
   GitHub Actions → GitHub Pages.
9. **Проверка.** Сборка `expo export`, проверка типов `npx tsc --noEmit`,
   прогон в Chromium через Playwright (все вкладки, плеер, карта, автозапуск у
   остановки, сайт в подпапке как на GitHub Pages) и контрольная сборка под
   Android, чтобы убедиться, что телефонная версия не сломалась.

10. **Проверка «на всё».** Типы, сборки трёх платформ, `npm audit`,
    `expo prebuild` (итоговые разрешения Android/iOS), проверка данных
    маршрута скриптом, 8 сценариев в браузере. Нашли и исправили:
    - пустую карту без линии маршрута, если сервер карт недоступен;
    - остановку, засчитанную в 600 м от маршрута (скачок GPS);
    - ложный «разворот» после возврата на маршрут;
    - «вы не на маршруте» при запуске приложения дома;
    - повторные поездки без автозапуска (пройденные остановки молчали навсегда);
    - «пружинящую» вместе со страницей нижнюю панель на iPhone и тормоза
      прокрутки из-за размытия фона;
    - растянутый на весь экран компьютера интерфейс.

Чему это учит: ИИ быстро пишет код, но проверять нужно в настоящем браузере —
проблемы 3–6 выше нашлись только при запуске, по коду их видно не было.

## Ограничения

- **Сайт работает, только пока вкладка открыта и экран включён.** Если свернуть
  браузер или заблокировать телефон, гид перестанет следить за маршрутом. Для
  поездки «телефон в кармане» нужно приложение (способ 2 или 3).
- Автозапуск рассказа на сайте — после первого касания страницы.
- Карта и пешеходные маршруты загружаются из интернета (OpenFreeMap,
  routing.openstreetmap.de).
- Голос в записях пока синтезированный, английских записей нет.
